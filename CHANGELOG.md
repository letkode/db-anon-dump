## [0.3.0] - 2026-11-20

### Added
- Progress while running: one line per table as it is copied (`structure [37/114] table`, and
  `data [37/114 ~41%] table` with an approximate percentage from the table sizes of the source), a heartbeat
  every 10 seconds saying which table is taking long and how much has been received, per-table durations while
  anonymising (with the tables currently in progress), and bytes processed when importing a dump
  (`--from-dump`) and when writing the final dump. All of it also goes to the run log.
- `--verbose` (`run`, `check`): container name, table list, startup time and the database driver's own
  messages. Without it the driver's `unexpected EOF` retries while the temporary database boots are hidden.
- `audit:` section in `config.yaml` (`names`: case-insensitive regular expressions on column names, `types`:
  data types). When present it replaces the built-in lists completely, so it works for databases whose names
  are not in English. `config.yaml.dist` now lists the full built-in defaults.
- `check --suggest`: writes `columns.suggested.yaml` next to `config.yaml` with every flagged column and a
  commented-out suggestion based on its name and type (length-aware; "decide" notes for free text, JSON and
  ambiguous names). Nothing is active until it is uncommented and renamed; `columns.yaml` is never touched.
- `docs/USO.md`: the complete usage guide (download, every file and option, progress, audit, suggest, logs,
  troubleshooting, CI). The README is now a short overview that links to it.

- `tables.schema_only` (and `--schema-only LIST`): tables dumped with their structure but without rows. Names,
  globs and `*`; the command-line list is added to the config's one; `exclude` still wins. `--schema-only '*'`
  (or `schema_only: ["*"]`) makes a structure-only dump: the file name gets `-schema`, and an empty `columns.yaml`
  needs no `--allow-empty`. schema_only tables are not anonymised, audited or suggested; with `--from-dump` they
  are emptied after the import.

- A `schema_only` spec that matches no extracted table now prints a warning (it used to be silent, so a typo
  went unnoticed).

- CI: a `smoke-macos` job (macOS runner, no Docker) runs the unit tests, builds the darwin binary, runs
  `version` and validates a project generated by `init`. The release notes say which binaries are tested end to end
  (linux-amd64, linux-arm64) and that darwin-arm64 is not.

### Fixed
- Column names with spaces or accents (`"Apellido Paterno"`) were rejected by `columns.yaml` validation, so such
  columns could not be anonymised. Only control characters are refused now; the dialect already quotes them.
  `check --suggest` quotes them in the YAML key and inside the patterns.
- `check --suggest` proposed `{MD5(column)}` for secrets, which the post-UPDATE check can never match (the hash of
  a hash is another value; exit 6). Suggestions now build hashes from `id` (`MD5(CONCAT(id, ''))`, portable: PostgreSQL's `md5()` rejects integers); tables without `id` get `{NULL}`.
- `check` / `--strict` / `--suggest` listed the columns of `schema_only` tables (which have no rows) in the audit.

### Changed
- The default `output` is now `output/dev-dump-{datetime}.sql.gz` (it was `{date}`), so two runs on the same day
  never overwrite each other. `{date}` is still accepted in `output` and `-o`.
- An empty `columns.yaml` is no longer a validation error: `validate` and `check` accept it with a warning.
  `run` refuses it (exit 3) unless `--allow-empty` is passed, because the dump would contain the real data.
- `plan.Audit` carries structured columns (table, column, type, length, nullability, has `id`) instead of strings.
- The structure/data copy between the source and the temporary database now streams through a counter that
  drives the progress display (same data, same order).

## [0.2.0] - 2026-11-19

### Added
- The source password is now read automatically from `.env` files next to `config.yaml`
  (`DBANONDUMP_SOURCE_PASSWORD`, or the name set in `source.password_env`). Files are merged in this order,
  the last one winning: `.env`, `.env.local`, `.env.<APP_ENV>`, `.env.<APP_ENV>.local`. `APP_ENV` comes from
  the environment or from `.env` / `.env.local`; without it only the first two are read. A variable already
  set in the real environment always wins over the files, and missing files are skipped.
- `dbanondump init` also writes `.env` (mode 0600) from the new `templates/.env.dist`.
- `.env`, `.env.*` (except `.env.dist`) added to `.gitignore`.
- New dependency: `github.com/joho/godotenv` (parses the `.env` files).
- Run log: `run` and `check` write `logs/<command>-<datetime>.log` (mode 0600) with every console line
  timestamped, the error and exit code on failure, and a summary with the total duration and the time of each
  phase (temporary database, structure, pre-flight, data extraction, anonymise, dump, cleanup). The source
  password is redacted. Configure it with `logs.dir` (`""` disables) and `logs.keep` in `config.yaml`, or with
  `--log-dir` / `--no-log`. `logs/` added to `.gitignore`.

### Changed
- `init` now writes four files (`config.yaml`, `columns.yaml`, `functions.yaml`, `.env`) and refuses to run
  if any of them already exists (unless `--force`).
- The "missing password" error now also mentions the `.env` path that was looked up.

## [0.1.0] - 2026-11-18

First release.

### Added
- `dbanondump run`: extracts the selected tables into a throwaway database (temporary Docker container),
  anonymises them with the patterns of `columns.yaml`, runs the post-anonymisation checks and writes the dev
  dump (`.sql` or `.sql.gz`). The temporary container is removed at the end, even on errors.
- Engines: MySQL, MariaDB and PostgreSQL (one engine per project; patterns are written in that engine's SQL).
- `dbanondump check`: validates against the real structure and lists personal-looking columns without a
  pattern (`--strict` exits 3 if any); loads no data and writes nothing.
- `dbanondump validate`: offline lint of the three configuration files, with no Docker or database.
- `dbanondump init [--force] [dir]`: writes commented starter `config.yaml`, `columns.yaml` and
  `functions.yaml` (templates embedded in the binary).
- Source can be a live database (read-only account) or an existing dump (`source.dump_file` / `--from-dump`).
- Table selection with names, globs and excludes (`--tables`, `--exclude`).
- Source password taken from an environment variable (`DBANONDUMP_SOURCE_PASSWORD`).
- Static binaries for linux/amd64, linux/arm64 and darwin/arm64 with `SHA256SUMS`, published by the
  `Release` workflow when a version tag is pushed.
- CI: `go vet`, unit tests and end-to-end tests for MySQL, MariaDB and PostgreSQL.
